01 / USE WITH AN AGENT

Start with a conversation.

Connect an MCP client, then ask it to create and use a Bog. You need a token from the service owner; there is no public signup or OAuth login.

Connect Codex

Load your token into BOG_CLOUD_TOKEN before launching Codex. Add this to ~/.codex/config.toml, then start a new client session.

config.toml
[mcp_servers.bog_cloud]
url = "https://flower-bog-cloud.fly.dev/mcp"
bearer_token_env_var = "BOG_CLOUD_TOKEN"

Other MCP clients need Streamable HTTP and a bearer-token header. Clients that require OAuth are not supported yet. Use an owner token to create Bogs; a scoped token can only work inside its assigned Bog.

Then ask for what you need

“Create a Bog called reading-list. Save a book under the key dune, with its title and reading status. Read it back and tell me how many records I have.”

The agent can create, list and describe Bogs; read, replace and delete records; submit batches; and read views. Your client's normal tool approvals still apply.

Good first projects: an agent notebook, a small personal catalog, or shared state for an internal script.

02 / USE THE API

From nothing to a record.

Run these examples in one Bash terminal with curl and jq installed. All data requests require a bearer token. Keep credentials in your server or terminal, never in a public frontend bundle.

01

Set your connection

Enter an owner token at the hidden prompt. It stays in this terminal session; the page never receives it.

Bash
export BOG_CLOUD_URL=https://flower-bog-cloud.fly.dev
printf 'Owner token: '
read -r -s BOG_CLOUD_TOKEN; printf '\n'
export BOG_CLOUD_TOKEN

bog() {
  curl --fail-with-body --silent --show-error \
    -H "Authorization: Bearer $BOG_CLOUD_TOKEN" \
    -H 'Content-Type: application/json' "$@"
}
02

Create a Bog

Creation returns an ID and starts the store. Keep the same idempotency key when retrying this request; a new key creates a new Bog.

POST /v1/bogs
CREATE_KEY=$(uuidgen)
CREATED=$(bog -X POST "$BOG_CLOUD_URL/v1/bogs" \
  -H "Idempotency-Key: $CREATE_KEY" \
  -d '{"name":"reading-list","template":"records-v1"}')
BOG_ID=$(printf '%s' "$CREATED" | jq -er '.id')
export BOG_ID
printf 'Bog: %s\n' "$BOG_ID"

# Repeat until status is "ready" before writing.
bog "$BOG_CLOUD_URL/v1/bogs/$BOG_ID" | jq
03

Write, then read

Each key holds one JSON object. Writing the same key again replaces the entire object. Nested objects and arrays are welcome.

PUT + GET /docs/{key}
bog -X PUT "$BOG_CLOUD_URL/v1/bogs/$BOG_ID/docs/dune" \
  -d '{"title":"Dune","status":"to-read","tags":["fiction"]}'

bog "$BOG_CLOUD_URL/v1/bogs/$BOG_ID/docs/dune" | jq '.data'

# Returned record:
# {"title":"Dune","status":"to-read","tags":["fiction"]}
04

Read a Fold view

docs lists records; total counts them. Replacing a record keeps the count steady. Adding or removing a key changes it.

GET /views/{view}
bog "$BOG_CLOUD_URL/v1/bogs/$BOG_ID/views/docs?limit=20&offset=0" | jq '.data'

bog "$BOG_CLOUD_URL/v1/bogs/$BOG_ID/views/total" | jq '.data.value'
# 1
Batch changes and delete a record +

A batch validates all operations before applying one transaction. This example adds two records, then removes one.

POST /batch · DELETE /docs/{key}
bog -X POST "$BOG_CLOUD_URL/v1/bogs/$BOG_ID/batch" -d '[
  {"op":"upsert","key":"solaris","data":{"title":"Solaris"}},
  {"op":"upsert","key":"piranesi","data":{"title":"Piranesi"}}
]'

bog -X DELETE "$BOG_CLOUD_URL/v1/bogs/$BOG_ID/docs/solaris"
Give an app access to just this Bog +

Use the owner token to issue a read or write token. Write includes read access. The raw token is returned only once: put it in your application's protected environment, and save its ID for revocation.

Owner only / scoped credentials
# This response contains a secret. Do not share it or log it.
bog -X POST "$BOG_CLOUD_URL/v1/bogs/$BOG_ID/tokens" \
  -d '{"scope":"write"}'

# Later, revoke it using the returned token ID:
# TOKEN_ID=the-returned-id
# bog -X DELETE "$BOG_CLOUD_URL/v1/bogs/$BOG_ID/tokens/$TOKEN_ID"

03 / AT A GLANCE

A small, deliberate API.

Bog Cloud API endpoints
MethodPathWhat it does
POST / GET/v1/bogsCreate / list Bogs. Owner only.
GET/v1/bogs/{id}Check identity and readiness.
GET/v1/bogs/{id}/schemaInspect the available schema.
PUT / GET / DELETE/v1/bogs/{id}/docs/{key}Replace, read, or remove a record.
POST/v1/bogs/{id}/batchApply a group of record changes.
GET/v1/bogs/{id}/views/{view}Read docs or total.
POST/v1/bogs/{id}/tokensIssue a scoped token. Owner only.
DELETE/v1/bogs/{id}/tokens/{token-id}Revoke a token. Owner only.

When a request fails

Errors include an error.code and a request_id. Keep the request ID when asking for help.

401 missing or invalid token · 403 insufficient permission · 404 missing or inaccessible resource · 409 conflicting creation request · 413 size limit · 429 capacity reached · 503 not ready or unavailable.

The current boundaries

JSON objects up to 256 KiB; 100 operations per batch; paged document views. Keys are at most 256 bytes and cannot contain slashes or control characters, or be just . or ... URL-encode keys.

This preview runs on one persistent host with eight instance slots. It has no SQL, joins, custom uploaded Fold views, public signup, or instance deletion yet. Backups and restores are operator-run; automatic off-host backups are not configured.
