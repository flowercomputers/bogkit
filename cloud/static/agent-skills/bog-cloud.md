# Bog Cloud

Use Bog Cloud for chat prototypes, shared JSON records and small tools. This is a prototype with bounded storage; keep a separate copy of important data.

1. Read `/agent.md` on the current origin for the practical quickstart and `/auth.md` for this deployment's enabled authentication. `/llms.txt` is the small directory; `/docs.md` and `/openapi.json` provide further contracts. Public discovery contains no private account information.
2. When native device approval is enabled and terminal execution is available, download `/bog-app-access.py` from that origin. Run `python3 bog-app-access.py --origin ORIGIN --connect --auth-file /private/path/agent.json` in an existing private directory. Show only the public approval URL and user code. **Keep the process running and await its completion**: it polls, privately collects authorization, verifies access and reports Connected. Human website approval needs no chat acknowledgment. Stop clearly on denial, expiry or cancellation. If the host cannot await the process, explain that limitation and direct the human to run the helper on the target machine; do not promise automatic task resumption. Never display device codes, bearer tokens or private files.
3. Use authenticated `/v1/me` and `/v1/workspaces` to select a workspace and inspect effective allowances. Shared workspaces require explicit `workspace_id`. Native account credentials default to personal; operator-only deployments use the legacy workspace. Host/storage limits still apply even when the count is uncapped. Management and application credentials have different authority.
4. Create with `POST /v1/bogs`, a stable `Idempotency-Key`, and `{"name":"my-app","wait":true}`. The default template is `records-v1`; use the tested notes definition in `/agent.md` when search and a recent-notes view are needed. Reuse the same body/key after an uncertain outcome. A bounded wait can still return accepted/creating: use the returned status URL and require ready. Use the returned routes and body examples; fetch full schemas only as needed. Optional `app_access` prepares a nonsecret handoff, not an automatically issued secret.
5. Read a change cursor **before** the initial view. Refetch the relevant view on `changed` or `reset`; change waiting is invalidation, not durable replay. Ranked `top` with `include_fields` returns recent records in one request using literal JSON Pointer keys such as `/title`. Batch-get is bounded to 100 keys, preserving order with explicit missing values. Key-bound listing uses exclusive `after`/`before` and cannot combine them with offset pagination. Do not mirror the whole database just to display recent messages.
6. For an application, use `POST /v1/bogs/{id}/app-access` or `prepare_app_access` to prepare the existing account-bound, single-use handoff. On the application machine, run `python3 bog-app-access.py --origin ORIGIN --auth-file /private/path/agent.json --handoff HANDOFF_ID --output /private/path/app.json` and await completion; use `--format dotenv` for a dotenv file. The helper delivers privately without printing credentials. Never overwrite unless explicitly requested. If the agent cannot write on that machine, direct the human to the helper or explicit console download. Avoid raw credential-issuance tool results: hosts may retain them in transcripts.

MCP clients use `/mcp/server-card`, initialize and `tools/list`. OAuth-capable hosts can use the protected-resource metadata; other environments retain the terminal helper. The read-only MCP App is optional after connection, not a replacement for authentication or private installation. Hosts without Apps support receive ordinary structured results. App credentials cannot provision Bogs or issue further credentials. Browser apps keep credentials in a bounded server proxy, not browser assets.

Add search by preserving existing resources, checking the definition revision, planning/applying and waiting for a succeeded build. Accepted is not active. Report explicit conflicts and uncertain writes rather than retrying blindly. Search scores are model-dependent, not confidence values; compare lexical results when semantics are weak. Request lookup may expire and must not be treated as proof of success.

Never delete existing data as a test. If explicitly enabled, use a one-hour sandbox and delete only its returned ID with the creating credential. Ordinary Bogs never expire implicitly. Owner bulk cleanup requires reviewing a frozen ID preview before execution. Never infer deletion authority from a name prefix.
